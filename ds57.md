# StatScout Pre-Launch Audit

## 🔴 Apple Will Reject

### 1. Privacy Manifest Is Empty
**File:** `StatScout/PrivacyInfo.xcprivacy`

Both `NSPrivacyCollectedDataTypes` and `NSPrivacyAccessedAPITypes` are empty arrays. Apple requires apps using certain APIs to declare them. This app uses:

- **UserDefaults** — `TeamsViewModel` stores favorite team. Needs `NSPrivacyAccessedAPICategoryUserDefaults` with reason `CA92.1`.
- **File timestamp APIs** — `DiskPlayerCache` calls `attributesOfItem(atPath:)` checking `.modificationDate`. Needs `NSPrivacyAccessedAPICategoryFileTimestamp` with reason `0A2A.1`.

**Fix:** Add these to the `NSPrivacyAccessedAPITypes` array in `PrivacyInfo.xcprivacy`.

### 2. URL Path Inconsistency — Dead Links
Three files hardcode `/baseball/` but the App Store submission doc references `/statscout/`:

| File | URLs |
|------|------|
| `StatScoutApp.swift:60` | `jackwallner.github.io/baseball/support.html` |
| `PaywallView.swift:212,217` | `/baseball/privacy-policy.html`, `/baseball/terms.html` |
| `SettingsView.swift:151,164` | `/baseball/support.html`, `/baseball/privacy-policy.html` |

Apple reviewers click every link. If the live GitHub Pages site is at `/statscout/` (as the submission doc says), these will 404 and the reviewer will reject.

**Fix:** Align all URLs to the actual live path, or set up redirects from `/baseball/` to `/statscout/`.

### 3. Paywall Lists Feature That Doesn't Exist
`PaywallView.swift` lists "Share Player Cards" as a Pro feature. But `shareSummary` on `Player` (line 101) is computed and never used — there's no `ShareLink` or share button anywhere in the UI. Test and UI test files reference `ShareLink` but no production view renders it.

**Fix:** Either implement the share feature or remove it from the paywall copy.

## 🟡 High Priority (Will Cause Problems)

### 4. StandardStatsLeadersView Has No Pro Gating
`PaywallView.swift` lists "Metric Leaderboards" as a Pro feature, but `StandardStatsLeadersView` accepts players without any `store.proStatus` check. It's accessible from the team view without gating.

**Fix:** Add Pro check to `StandardStatsLeadersView` or remove "Metric Leaderboards" from paywall copy.

### 5. SampleData.swift Ships in Release Builds
`SampleData.swift` is compiled into every build including Release. While only used by `PreviewStatcastAPI` (previews and default init), the struct and 6 hardcoded MLB player profiles are in the binary. Apple reviewers occasionally flag test/fake data in production binaries.

**Fix:** Wrap in `#if DEBUG` / `#endif`.

### 6. DashboardViewModel Falls Back to Sample Data on Any Error
`DashboardViewModel.swift:77-86` — any network, decode, or server error triggers loading `SampleData.players`. In production, this means a backend outage silently shows Aaron Judge instead of an error state. Apple reviewers may see fake data and think it's a bug.

**Fix:** Only use sample data in `#if DEBUG`. Show proper error states in production.

### 7. Hardcoded $4.99 Fallback Price
`StoreManager.swift:55` — `proPrice` returns `"$4.99"` if products haven't loaded yet. If the App Store products fail to load during review, the paywall shows a stale price that may not match the actual IAP price.

**Fix:** Show "—" or hide price until products load.

### 8. Pro Tab Gating UX — Reviewer Friction
`RootTabView.swift:43-47` — tapping Teams or Metrics tabs when not Pro bounces the user back to tab 0 and shows a paywall. There's no context about *why* — the user sees a lock icon, taps it, and gets bounced. Apple reviewers hate "dead end" tabs especially when the lock icon invites tapping.

**Fix:** Let the user navigate and show an upsell card inline, rather than a hard bounce.

## 🟢 Lower Priority (Won't Block Review)

### 9. Season Year Hardcoded to 2026 — Breaks in 2027
Hardcoded at 6 locations: `StatcastAPI.swift:25,29,73,77`, `PlayerCache.swift:79-80`, `DashboardViewModel.swift:234`. In 2027, `season=eq.2026` returns no data. Not urgent for this review but should be dynamic.

### 10. No StoreKit Configuration File
No `.storekit` file for local purchase testing in the simulator. Not required for submission but needed for final QA.

### 11. docs/index.html — App Store Badge Links to `#`
`docs/index.html:154` has a TODO placeholder. Fix after getting the App Store URL.

### 12. Backend Data Quality Issues (from bugs.md)
`backend/ingest.py` stores percentile strings in `value` instead of raw stats (CRITICAL-2), hardcodes `team: "MLB"` (HIGH-3), hardcodes position to `"Hitter"`/`"Pitcher"` (HIGH-4), never populates `games` (HIGH-2). These make production data look broken — but won't trigger App Store rejection since the reviewer tests with live data.
