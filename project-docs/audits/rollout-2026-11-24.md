## Good moments for the star prompt

1. Following a player (Follow tapped, not Unfollow). Following is the app's core action and the signal the Hot/Cold tab reads. The star turns yellow, which is a visible success.
2. A StatScout+ member building a new comparison matchup (replacing a player, moving a side to another season, or swapping sides). It is the paid feature delivering a result. A free user looking at the locked teaser does not ask.

Both are the only automatic triggers. Settings keeps its Rate row (deep link `?action=write-review`), which ends the passive asks. Sending feedback never does. Never during onboarding.

Judgment call: StatScout has no scored result, so these two are the closest "finished with a good outcome" actions. If Jack wants a narrower one, drop the comparison moment (delete `.requestsReview(after: comparisonMoment)` in `PlayerComparisonView.swift`).

## Held for Jack

- Whether following a player and a Pro matchup are the right star moments is a product call (see above).
- `trial_cta` has no experiment yet. To run it, add `trial_cta` (`my` or `your`) to the metadata of an offering in a RevenueCat Experiment. `rating_prompt: off` must be set the same on every offering.
- The three new `.swift` files (`RemoteConfig.swift`, `ReviewRequest.swift`, `RemoteConfigTests.swift`) are not in the tracked `StatScout.xcodeproj` because xcodegen is not installed on this fleet machine. gh-sim regenerates the project, so builds and tests are fine. Run `xcodegen generate` on the Mac before the next local build.
- Japanese and Korean "my" and "your" lines are literal (`私の`, `あなたの`, `내`, `당신의`), which read stiff in those languages. Worth a native check before an experiment ships arms there.
